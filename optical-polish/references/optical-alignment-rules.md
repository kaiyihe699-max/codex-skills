# 光学对齐规则

## 目录

1. 证据模型
2. 图标和方向性形状
3. 按钮和组合内容
4. 边框与暗色界面
5. 阈值与判断

## 1. 证据模型

同时使用三类证据，不要只依赖其中一种：

1. **反差加权重心**：按前景相对背景的可见反差与透明度计算视觉质量分布。
2. **负空间平衡**：比较可见边界框到容器四边的距离。
3. **形状语义**：识别方向、开口、尖角、描边和有意不对称。

脚本默认把重心修正与负空间修正按 65% / 35% 合并。两种结果方向相反或差异很大时降低置信度，并进行人工复核。

## 2. 图标和方向性形状

- 圆形、弧形和尖角在几何边界上通常需要少量 overshoot；不要把可见边界严格压进同一方框。
- 播放三角形的面积重心偏向底边，视觉居中时通常需要向尖角方向移动。
- Chevron、返回箭头和纸飞机等开口图形具有明显方向性。先看反差重心，再看开口侧的负空间，不要只看 SVG viewBox。
- 描边图标按实际描边像素测量，不按路径中心线测量。相同 `stroke-width` 不代表相同视觉重量。
- 实心图标和线性图标并排时，优先匹配视觉面积与黑度，不强求同样的外接框尺寸。
- 品牌标志和具有识别性的非对称符号只报告偏移，不自动修正。

## 3. 按钮和组合内容

- 把图标、间距和文字作为一个视觉组检查整体重心。
- 再分别检查图标与文字的局部对齐，避免“整体居中但内部关系松散”。
- 左右留白相同不一定视觉相同；较暗、较细或开口的图标通常显得更轻。
- 图标加文字按钮的建议优先使用整数像素；小于 1 px 的偏移在高分辨率或矢量环境中验证。
- 文本内容变化后重新测量。`下载`、`继续`、`100%` 和 `¥1,299` 的可见重心不同。

## 4. 边框与暗色界面

- 边框视觉重量同时受宽度、透明度、亮度反差和相邻填充影响。
- 深色背景上的浅色 1 px 边框可能比浅色背景上的深色 1 px 边框更显眼。
- 使用 `--border-width` 将已知边框从内容重心中排除，并报告 `apparent_border_weight`。
- 不把阴影当作边框。阴影应在分析前移除或使用不含阴影的组件裁切。

## 5. 阈值与判断

- 建议偏移 `< 0.75 px`：通常视为平衡。
- `0.75-1.5 px`：轻微差异，做 A/B 闪切验证。
- `1.5-3 px`：通常可见，适合给出明确建议。
- `> 3 px`：先检查裁切、背景估计和组件范围，再判断是否确有偏移。
- 低置信度时不要自动应用修正。

这些阈值是 UI 组件的实用起点，不是普遍视觉定律。最终结论应结合尺寸、设备像素比、字体和品牌语言。
